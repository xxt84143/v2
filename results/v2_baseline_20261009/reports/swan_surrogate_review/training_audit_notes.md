# 训练端审计笔记

审计对象：当前 `TRAIN_SERVER/` 与 `toy_runs/hs_unet/`。只读取现有代码、日志、指标及官方文档，没有重训，也没有修改训练代码或 checkpoint。本笔记供主报告交叉核查，数据生成与缺失样本的结论以数据审计为准。

## 1. 训练本身在优化，但泛化没有同步改善

`train.py:46–50` 的损失为湿点上的归一化 Hs 均方误差；`train.py:72–75` 按湿点数汇总；`train.py:187` 以 `sqrt(loss) * hs_scale_m` 还原米制 RMSE。当前 Hs 缩放因子是 5，因此 MSE 乘 25 才是 m²，RMSE 乘 5 才是 m。

| Epoch | 日志训练 RMSE 等效值 / m | 验证 RMSE / m | 验证/训练 MSE 比 |
|---:|---:|---:|---:|
| 1 | 0.633258 | 0.549229 | 0.75 |
| 2 | 0.356644 | 0.527539 | 2.19 |
| 16 | 0.104801 | 0.504457 | 23.17 |
| 60 | 0.037356 | 0.527837 | 199.65 |
| 65 | 0.084622 | 0.483982 | 32.71 |
| 80 | 0.032820 | 0.536529 | 267.24 |

来源：`toy_runs/hs_unet/history.csv`，训练列按 `5 * sqrt(train_loss)` 复算。这里的训练 RMSE 是一轮中各 batch 更新前损失的换算，**不是**固定 `last.pt` 在完整训练集上重新评估的精确 RMSE。日志定义见 `train.py:60–74`。

可确认：网络可以把训练样本拟合得很低，验证误差却长期在约 0.51–0.55 m，属于显著的泛化差距，不能解释为“模型完全没学动”。这同时可能反映重复海况数量少、海况组合覆盖不全、架构偏置和泛化难度，不足以单独证明模型参数量就是主因。

80 轮中没有一轮整体验证 RMSE 优于边界 Hs 插值基线 0.331709 m。基线对应归一化 MSE 为 0.00440123，而最好的模型为 0.00936955。只做早停不能把当前实验挽救到超过基线。

最佳 checkpoint 是 epoch 65；次好为 epoch 16 的 0.504457 m。63–66 轮的训练 RMSE 依次为 0.044071、0.065132、0.084622、0.105714 m，期间验证值依次为 0.553204、0.559053、0.483982、0.532896 m。65 轮是一个孤立低点，说明当前最优对一次训练轨迹有敏感性；不能仅凭该现象断言学习率过高或数值异常。

## 2. 明确的主要失败维度是新海况

| 全部 | 121 | 0.484239 | 0.331709 | -0.256563 | -1.1311 |
| new_island | 37 | 0.109572 | 0.342041 | +0.069061 | +0.8974 |

来源：`toy_runs/hs_unet/evaluation/validation/metrics_by_group.csv:2–5`。Skill 是 `1 - MSE_model / MSE_baseline`，不是 RMSE 相对变化；总体 -1.1311 表示模型 MSE 为基线约 2.1311 倍。

网络对这些新岛形、旧海况的样本有明确增益，而对新海况发生大幅负偏差。这更符合“有限海况下学到了空间响应，但没有形成可靠的海况连续映射”，而非“U-Net 不会处理这个空间网格”。该解释仍然只适用于当前受控合成岛形族，不外推到真实海岸线。

`metrics_by_case.csv` 汇总可见新海况只有 F013、F014、F015，分别 28 个跨岛 case；其模型 RMSE 分别为 0.214974、0.549711、0.808197 m，Bias 分别为 +0.063449、-0.490773、-0.778689 m。详细分解由主报告的数据诊断给出。

## 4. GroupNorm：重要假设，但目前不能定罪

当前工厂显式构造 MONAI `BasicUNet`，5 个编码尺度与 4 次下采样，特征宽度 `(16,16,32,64,128,16)`，`GroupNorm(num_groups=4)`，`dropout=0.0`。工厂未覆盖的默认值由 MONAI 提供，包括 LeakyReLU 与反卷积上采样，最后输出为原始回归值。[MONAI 1.5.2 文档](https://monai.readthedocs.io/en/1.5.2/networks.html#basicunet)、[对应版本源码](https://github.com/Project-MONAI/MONAI/blob/1.5.2/monai/networks/nets/basic_unet.py)。

GroupNorm 在每个样本内部，跨同组通道及空间位置计算均值与方差；训练与评估都使用当前输入统计，不依赖 BatchNorm 式 running statistics。因此不能用“batch size 小导致 BatchNorm 测试统计失配”解释当前实现。[PyTorch 2.12 GroupNorm](https://docs.pytorch.org/docs/2.12/generated/torch.nn.GroupNorm.html)。

从公式 `GN(z) = gamma * (z - mean(z)) / sqrt(var(z)+eps) + beta` 可推断：同一组特征共同正向缩放时，除 eps 效应外标准化后近似不变；共同平移会被消去。若绝对海况强度在隐藏层主要表现为这类缩放/偏移，幅值回归可能变难。**但本模型把水深、坐标、湿点、波高、周期、方向、风共同卷积，改变波高不等价于所有隐藏特征共同缩放；GN 也保留组内相对通道信息。因此不能证明绝对 Hs 已经被完全抹去，更不能把负偏差直接归因于 GN。**

最有诊断价值的控制实验是在同一数据与同一 split 上比较：现有 GN、移除 GN、保留 GN 但将原始海况幅值经独立分支注入最后解码层。再比较直接预测 Hs 与 `H_hat = H_boundary_interp + delta_theta(x)` 的残差结构。后二者为幅值提供明确通路，但都需要真实消融来确认增益。不能通过推理时临时关闭已有 GN 来代表“无 GN 训练”的对照。

## 5. 损失和模型归纳偏置需要改进的方向

1. 当前唯一优化目标是湿点 Hs 的绝对 MSE。它对大面积海域、较大绝对误差提供更多权重，不会专门强调背浪遮蔽、岸边或浅水区。当前整体失败不能靠加入梯度损失直接解释或保证修复；先修复海况幅值映射，再按水深、岸距、入射侧/背浪侧分层验证。
2. 边界 Hs 插值已经是强基线。当前直接回归让网络重学容易获得的背景幅值。残差回归可以把初始输出置于已知基线上，并把容量用于地形与风造成的修正。它没有保证永远优于基线，仍需逐 forcing 的 skill 检查。
3. 对海况样本的增加应优先增加独立 forcing 数量，而不是只把已有少数 forcing 配到更多相似岛上。空间像素数不能当作独立物理情景数。
4. 固定 lr 的 AdamW、无学习率调度、无显式早停、无 dropout/augmentation，均可从 `train.py:145,180–203` 与 `model_factory.py:13–14` 确认。小数据下可以消融学习率衰减、更窄模型与 weight decay，但不能用一套超参数的表现判定整个 U-Net 家族不可用。
5. 不能随意扰动输入海况而沿用原 SWAN 标签。旋转增强也必须同步旋转所有空间场、风向量、波向向量及角点边界顺序，并判断经纬网格与物理设定是否允许这种对称性。

## 6. 评估比代码计算更需要警惕的统计问题

### Case bootstrap 的独立性假设

`evaluate.py:89–101` 将每个 case 视作独立单位抽样，`104–128` 给出 case 指标的宏平均置信区间。但 case 来自 terrain×forcing 的交叉组合，许多 case 共享同一 forcing。new_forcing 的 72 个 case 实際只覆盖 3 个新 forcing。当前置信区间描述的是当前 case 集合的重采样，不应解读为对任意新海况的可信区间；共同海况效应可让它低估不确定性。

建议同时报告每个 forcing 的误差、各 forcing 等权宏平均，以及按 forcing 分块/地形海况交叉分组的评估。只有 3 个新 forcing 时，增加 bootstrap 重复次数并不会增加物理样本信息；仍需更多独立 held-out forcing 或多套分组拆分。

### 全局 R² 与空间 R²不是同一问题

`evaluate.py:64–83` 的 R² 是在传入数组上计算。汇总时 `106–110` 把所有 case 像素拼在一起，所以全局 R² 同时包含 case 间平均海况差异与 case 内空间差异。高全局相关系数不自动说明单幅波场的细节准确；单 case 目标近乎平坦时，R² 又可能因分母很小而极负。应合看 RMSE、bias、去均值空间误差和单 case R²，不能只选有利的指标。

### 80 次 checkpoint 选择

`train.py:190–195` 每轮按全部验证湿点 MSE 选择 best，这是合理的基本流程，也没有使用测试集选模型。但同一小验证集被用来选 80 次候选并不产生 80 份独立证据。当前只有一次随机种子的训练记录，不能量化优化随机性，更不能把 epoch 65 的孤立改进当成稳定规律。也不应把“80 次”机械视作 80 次独立检验，因为这些 checkpoint 强相关。

另需区分：整体像素加权最优、按 forcing 等权最优、三个泛化组中最坏组最优是不同目标。当前选择准则只对应第一个。建议先确定将来用途，再固定选模准则，并把封存测试集只用于最终确认。

### 自动质量门槛目前没启用

`evaluate.py:451–470` 支持 RMSE/R²/skill 门槛，但现有 summary 全部为 null，`quality_gates_passed` 也是 null。脚本成功退出表示评估过程完成，不表示模型达到性能标准。对于这个草稿，最低可执行门槛可以先定义为各主要新海况组相对边界基线有正 skill，而不提前承诺任意绝对精度。

## 7. 有关复现与审计的次要改进

- `run_config.json` 记录 torch/CUDA，未记录 MONAI 实际版本、训练源代码 SHA 与完整依赖锁定；工厂版本虽在 requirements 固定，独立记录实际导入版本更利于长期复现。此项是溯源限制，不是已确认的误差来源。
- `training_core.py:96–117` 按 `(shard parent, terrain_id/forcing_id)` 定义身份。对于当前单 tile 正常；未来多 tile 如果 forcing ID 代表全局相同海况，按 tile 命名空间隔离会漏掉跨 tile 的同一 forcing 重用，需要按物理身份/内容 hash 审计。
- 校验器验证“标为 new 的身份没有出现在 train”，没有显式验证 `new_island` 中 forcing 必须是 seen、`new_forcing` 中 terrain 必须是 seen。当前分组是否真实符合预期需从 manifest 实查；不能仅以校验器成功通过为依据。
- 校验器确认张量形状、有限值、mask、padding、原始波风节点合同；它没有重新由 wave/wind 推导所有 x 通道并逐点比较。因此 hash 确保交付一致，不证明转换算法语义正确。
